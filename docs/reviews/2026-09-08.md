### F-033 — 직접 실행하는 shell entrypoint의 실행 권한 보장

위치: `scripts/remote-install.sh:143`, `scripts/manage.sh:254`, `scripts/manage.sh:279`; Git의 `scripts/install.sh`와 `scripts/remote-install.sh` mode는 `100644`다.

bootstrap은 clone 후 `"${INSTALL_DIR}/scripts/install.sh"`를 실행하고 manager도 installer/bootstrap을 직접 실행한다. 깨끗한 Linux Git checkout은 실행 비트를 만들지 않으므로 원격 SHA 설치와 checkout 기반 repair/update가 `Permission denied`, exit 126으로 중단된다. Windows의 `core.filemode=false`와 `bash scripts/install.sh` 로컬 실행으로는 드러나지 않는다. Git 저장 권한을 보존한 임시 artifact에서 직접 실행이 126으로 끝나는 것을 확인했다.

수정 방향: 실행 entrypoint를 Git에서 `100755`로 관리하거나, 신뢰한 Bash로 명시적으로 실행한다. checkout과 최종 release artifact 양쪽에서 bootstrap→installer 및 manager→installer/bootstrap을 검증한다.

### F-034 — supervisor의 background child에 원래 stdin 전달

위치: `scripts/freebuff-wrapper.sh:198`~`202`.

wrapper는 job control이 꺼진 비대화형 Bash에서 `setsid --wait ... &`를 실행하면서 stdin을 별도로 연결하지 않는다. 이 비동기 명령의 입력은 `/dev/null`이 된다. stdin으로 `review-input\n`을 넣고 `proot-distro` 자리에 한 줄을 읽는 fixture를 두면 `input=EOF`를 반환한다. TUI나 입력 대기는 사용자가 연 터미널을 받지 못한다.

수정 방향: background 실행 전에 stdin FD를 보존하고 child에 명시적으로 연결한다. `setsid`와 signal 전달을 유지하면서 파이프 입력과 실제 PTY 입력·raw mode·Ctrl-C·터미널 복구를 각각 확인한다. 이번 재현은 파이프 입력이며 실제 Android PTY 검증은 별도다.

### F-035 — URL queue를 PRoot에서 보이는 경로로 전달

위치: `scripts/freebuff-wrapper.sh:31`, `scripts/freebuff-wrapper.sh:202`, `scripts/xdg-open-bridge.sh:49`~`60`.

wrapper는 `--isolated --shared-home`으로 로그인하면서 URL queue를 `/data/data/com.termux/files/home/.cache/.../login-url`이라는 host 경로로 전달한다. bridge도 이 host 경로만 허용한다. 공식 PRoot-Distro의 normal/root container 계약은 HOME을 `/root`에 bind하며 isolated 모드에서는 HOME의 원래 위치를 자동 bind하지 않는다. 따라서 깨끗한 Ubuntu/Debian guest에서는 bridge가 찾는 session 디렉터리가 없고 exit 3 경로로 빠진다.

이는 [공식 HOME·isolated 설명](https://github.com/termux/proot-distro#login--start-a-shell-inside-a-container)과 [bind 구성 소스](https://raw.githubusercontent.com/termux/proot-distro/master/proot_distro/commands/login/proot_cmd.py)의 `_add_non_minimal_binds`를 2026-09-08에 대조한 결론이다. 실제 기기 재현 완료를 뜻하지 않는다. 기존 동시 URL 테스트는 host에서 queue에 직접 쓰므로 이 guest 경계가 빠져 있다.

수정 방향: host 소비 경로와 guest 쓰기 경로를 따로 계산하거나 session 디렉터리만 고정 guest 위치에 bind한다. bridge의 경로 제한도 함께 변경하고 실제 `xdg-open`→queue→watcher 전체 흐름을 검사한다.

### F-036 — CWD 이동 실패 시 실행 중단

위치: `src/proot/freebuff-launcher.ts:274`~~`276`, `src/proot/proot-wrapper.ts:235`~~`237`, `scripts/freebuff-wrapper.sh:201`.

세 경로 모두 `cd ...; shift; exec ...`이고 inner Bash에는 `set -e`나 `cd ... || exit`가 없다. 프로젝트가 삭제되거나 guest에서 mount되지 않으면 `cd`만 실패하고 기존 guest HOME에서 FreeBuff를 실행한다. 코딩 도구가 잘못된 프로젝트를 읽거나 변경할 수 있다.

공개 `buildCommand()`가 만든 inner argv를 그대로 실행하고 고정 FreeBuff 위치에 무해한 `pwd` fixture를 두었다. 없는 `/missing-review-project`에 대해 `cd` 오류 후 `FREEBUFF_RAN cwd=<이전 디렉터리>`, exit 0을 확인했다.

수정 방향: `cd -- "$1" || exit`처럼 실패를 명시적으로 반환한다. wrapper의 세 번째 위치 인자도 같은 규칙을 적용한다. 없는 CWD에서는 FreeBuff fixture의 실행 marker가 생성되지 않아야 한다.

### F-037 — 직접 child의 close와 group 정리 완료를 분리

위치: `src/proot/freebuff-launcher.ts:179`~`190`.

TERM 후 직접 자식이 먼저 종료하면 `close` handler가 `cleanup()`을 호출하고 `forceKillTimer`를 취소한다. 같은 group의 손자가 stdio를 닫았거나 `ignore`로 실행되고 TERM을 무시하면 direct-child close는 손자의 생존을 막지 않는다.

실제 Linux Node parent는 기본 TERM 동작으로 종료하게 하고, 손자는 TERM을 무시한 채 1초 뒤 sentinel을 쓰도록 했다. timeout 500ms, grace 100ms인데도 `terminationReason=timeout` 반환 뒤 손자가 sentinel을 썼다. 재현에서 만든 PID는 종료 후 정리했다. 기존 Linux 테스트는 부모까지 TERM을 무시하므로 이 분기가 실행되지 않는다.

수정 방향: termination 시작 뒤 group 잔존 확인과 bounded KILL을 마칠 때까지 정리 책임을 유지한다. timeout/abort/host signal 각각에서 부모가 먼저 끝나는 케이스와 손자 stdio 분리를 검증한다.

### F-038 — 정상 종료에서도 PGID 정리 책임 유지

위치: `scripts/freebuff-wrapper.sh:239`~`241`.

main wait 뒤 PID와 PGID를 비우고 EXIT trap으로 들어가므로 `freebuff_group_alive`는 남은 group을 찾지 못한다. 정상 종료하는 `proot-distro` fixture가 같은 group에 손자를 남기면 wrapper는 exit 0을 반환하고 손자는 그 뒤 sentinel을 쓴다.

실제 PRoot의 기본 `--kill-on-exit`이 이 현상을 가릴 수 있으므로 실제 Termux에서 같은 누수가 관측됐다고 주장하지 않는다. 다만 wrapper가 소유한 group 전체를 정리한다는 계약과 구현은 일치하지 않는다.

수정 방향: group 정리를 완료한 뒤에만 식별자를 폐기한다. 정상 종료와 오류 종료 모두 자식·손자가 남는 fixture를 검사한다.

### F-039 — 조건식에서 호출되는 validator가 실패를 반환하도록 수정

위치: `scripts/manage.sh:60`~`63`, `scripts/manage.sh:145`.

JSON doctor는 `if ! validate_manifest_contract ...`로 검사한다. 이 문맥에서는 함수 안의 `set -e`에 기대어 중단할 수 없는데, 앞의 identifier/image validator 호출은 실패를 명시적으로 반환하지 않는다. 이후 path/hash 검사를 통과하면 함수가 성공으로 끝난다.

경로와 hash가 모두 정상인 schema 2 manifest에서 `proot_image=ubuntu:latest`만 지정했는데도 JSON `status=ok`, exit 0, stderr 없음이 나왔다. 기존 mutable-image Bats fixture는 필수 path/hash까지 누락되어 있어 잘못된 거부 이유로 통과한다.

수정 방향: 각 validator에 `|| return 2` 등을 적용한다. 유효한 manifest에서 필드 하나씩만 바꿔 identifier/image 검사가 독립적으로 실패하는지 확인한다.

### F-040 — doctor가 실제 실행 포인터를 검사하도록 수정

위치: `scripts/manage.sh:171`~`173`.

doctor는 versioned Node/FreeBuff 파일의 `-x`만 검사한다. wrapper와 launcher가 실제 사용하는 `current-node`, `current-freebuff` 링크는 확인하지 않는다. 두 링크가 모두 없는 fixture에서도 모든 check가 true이고 `status=ok`, exit 0이었다. 실제 실행 경로는 없으므로 preflight로 쓰기에는 잘못된 준비 상태다.

수정 방향: current 링크의 존재·대상·manifest 일치와 실제 guest 경로 해석을 확인한다. 링크 누락, 잘못된 버전, dangling link를 각각 degraded로 판정해야 한다. guest의 절대 symlink는 host `test -x`만으로 잘못 판정하지 않도록 주의한다.

### F-041 — checksum 계약에서 출처 주석을 실패 조건으로 보지 않기

위치: `tests/script-contracts.test.ts:114`, `scripts/install.sh:41`.

테스트는 installer 전체에 `SHASUMS256.txt`라는 문자열이 없어야 한다고 검사한다. 현재 installer는 기본 checksum을 상수로 고정하지만 출처 주석에 이 파일명이 있으므로 테스트가 실패한다. 샌드박스 제한을 제거한 Windows 전체 Jest에서도 이 한 건이 남았다: 171 pass, 1 fail, 3 Linux-only skip.

수정 방향: 주석을 지우기보다 실행 중 live checksum을 받아 신뢰하는 동작을 검사한다. 고정 digest의 실제 비교와 변조 archive 거부를 보장하고 출처는 보존한다.
